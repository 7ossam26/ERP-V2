ERP-V2 — Backend API Test Plan

Project: ERP-V2 (Node.js / Express / Prisma / MySQL) Branch: adam-testing Date: 2026-03-07 Phases: A1 – A8 (Backend only)

Pre-Testing Known Risks

JWT fallback secret — auth.js uses "fallback_secret_key_change_me" if JWT_SECRET is not set in .env
Treasury balance drift — Treasury.balance is a stored field, not calculated; any failed transaction path could cause drift
SaleItem dual-nullable FK — both itemId and bomId are nullable; at least one must always be set
Schema gap — production_orders table and items.is_bom field exist in schema.prisma but have no migration yet
Branch filter edge case — user with branchId=NULL and no accessibleBranches receives { id: 0 } filter → silent empty result
Concurrent open shifts — no unique constraint on shifts per user/branch/status observed in migrations
